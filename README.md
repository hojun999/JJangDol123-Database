# 볼링노트

GitHub Pages용 한국어 볼링 기록 웹사이트입니다. 조회는 공개, 저장·수정은 Supabase에 등록한 관리자만 가능합니다.

## 포함 기능

- 참가자 이름과 기본 일반/학생/회원 구분 등록
- 볼링장별 수기 요금제 등록: 이름, 적용 시간 설명, 일반/학생/회원 가격, 대화료
- 날짜별 방문 기록, 같은 날 여러 볼링장·여러 방문 지원
- 사진 여러 장을 순서대로 OCR 인식, A~D 행과 사람 연결, 확인 후 저장
- 기울어진 파란 점수판 보정, 우측 최종 점수 인식, 수동 인식 영역 지정과 직접 수정
- 직전 게임의 A~D 이름 연결 재사용
- 전체·날짜별 점수, 게임 수, 평균, 최고점, 누적 평균 그래프
- 요금제별 게임 수, 개인별 가격과 대화료 면제 수정, 정산 내용 복사
- 방문 당시 요금 보관, 점수 수정·게임/방문 삭제, JSON 백업/복원
- 모바일·PC 화면 지원

## 로컬에서 확인

Node.js 22 이상을 권장합니다.

```sh
npm ci
npm run dev
```

표시된 주소를 엽니다. Supabase 설정이 비어 있으면 **기기 내 미리보기**입니다. 수정은 가능하지만 기록은 해당 브라우저 localStorage에만 저장됩니다. 다른 사람에게 공유되지 않으며 브라우저 데이터 삭제 시 없어집니다. Supabase 연결 후 미리보기 기록은 자동 이전되지 않으므로 먼저 백업을 내보내세요.

## Supabase 연결

1. https://supabase.com 에서 새 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/schema.sql` 전체를 실행합니다.
3. Authentication → Users에서 관리자 이메일/비밀번호 계정을 만듭니다. 로그인 가능하도록 이메일 확인 상태도 설정합니다.
4. 해당 계정의 User UID를 `supabase/admin.sql`의 UUID 자리에 입력하고 SQL Editor에서 실행합니다.
5. 공개 회원가입이 필요 없으므로 Authentication 설정에서 신규 가입을 비활성화하세요. 관리자 추가는 대시보드에서 진행합니다.
6. 프로젝트 설정/연결 메뉴에서 Project URL과 **publishable key** 또는 legacy **anon key**를 확인합니다.
7. `public/config.js`에 입력합니다.

```js
window.BOWLING_CONFIG = {
  supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
  supabaseKey: 'YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY'
};
```

service_role, secret key, DB 비밀번호, 관리자 비밀번호는 소스에 넣지 마세요. 공개키만으로 수정할 수 없도록 DB·사진 저장소에 관리자 권한 정책을 적용합니다. 단순히 버튼만 숨기는 방식이 아닙니다. 관리자 목록에는 본인 계정만 조회할 수 있습니다. 방문 데이터에는 관리자 이메일을 저장하지 않습니다.

8. `npm run build` 후 배포합니다. 관리자 로그인하여 참가자와 첫 방문을 저장하면 공동 기록이 생성됩니다.
9. 미리보기 백업이 있다면 연결 후 관리자 로그인 → 참가자 → 백업 가져오기로 이전합니다. 로컬 사진은 이때 업로드합니다.

Supabase 실제 프로젝트 생성 및 연결 전에는 클라우드 저장·로그인·권한 동작을 실제 환경에서 검증할 수 없습니다. 연결 후 아래 확인을 완료하세요.

## GitHub Pages 배포

1. GitHub에서 `bowling-records` 등의 새 저장소를 생성합니다.
2. 이 폴더 전체를 저장소 루트에 업로드/커밋합니다. `.github/workflows/deploy.yml`도 포함해야 합니다. ZIP 안의 상위 `bowling-records` 폴더를 한 번 열고 그 안의 파일을 루트로 올리세요. `node_modules`와 `dist`는 소스 커밋에서 제외합니다.
3. 기본 브랜치는 `main`으로 사용합니다.
4. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
5. Actions 탭에서 `Deploy bowling note to GitHub Pages`를 실행하거나 `main`에 커밋합니다.
6. 배포가 성공하면 `https://사용자명.github.io/저장소명/`에 접속합니다. Vite base를 상대 경로로 설정하여 하위 경로 배포도 지원합니다.
7. 공개키 설정을 변경한 경우 다시 커밋/배포합니다. GitHub Pages는 데이터 저장을 담당하지 않고 Supabase가 기록·사진을 보관합니다.

소스를 새 저장소에 올리는 명령 예시:

```sh
git init
git add .
git commit -m "Build bowling records site"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/bowling-records.git
git push -u origin main
```

## 사용 순서

1. 참가자 등록 → 볼링장·요금제 수정/등록
2. 방문 기록 추가 → 날짜·볼링장·기본 요금제 선택
3. 날짜별 기록에서 이번 게임의 요금제 버튼 선택 → 사진 입력
4. OCR 결과의 행 수·점수를 원본과 비교하고 이름 연결 → 확인 후 저장
5. 다음 사진도 확인·저장. 같은 행의 사람은 직전 매핑을 이어 사용합니다.
6. 정산하기에서 게임 수·학생/일반/회원·대화료 면제 확인, 시간대가 바뀐 게임은 요금제별로 나눠 입력

A~D는 참가자 행입니다. 사진 속 `13` 같은 숫자는 실제 레인 번호이므로 참가자 이름으로 쓰지 않습니다. 우측 HDP 값이 최종 점수와 같은 현재 사진 형식을 대상으로 합니다. 핸디캡이 적용되어 10프레임 점수와 HDP 점수가 다른 볼링장은 어떤 값을 기록할지 별도 확인이 필요합니다.

평균은 저장한 개인 최종 점수의 합 ÷ 개인 게임 수입니다. 0점은 포함하며 중도 종료 사진은 올리지 않거나 건너뛰세요. 한 사진은 한 게임이며 최대 4명까지 기록합니다. 같은 사진을 두 번 올리면 두 게임으로 기록되므로 저장 전에 확인하세요.

## 요금과 기록 처리

- 시간대로 가격을 자동 추정하지 않습니다. 등록한 요금제를 버튼으로 직접 선택합니다.
- 볼링장 설정 변경은 새 방문에 적용됩니다. 기존 방문은 당시 요금 스냅샷을 유지합니다.
- 요금제에 가격이 없는 구분은 게임 저장을 막습니다. 예시 요금표의 락볼링 회원 가격은 확인되지 않아 비워져 있습니다.
- 사진 저장 시 인원별 정산 게임 수를 1게임씩 추가합니다. 정산 화면에서는 실제 청구 게임 수를 자유롭게 조정할 수 있습니다.
- 게임 삭제 후 정산 수량은 자동 차감하지 않습니다. 수정한 정산 수량과 충돌하지 않도록 직접 확인합니다. 기록 수와 정산 수가 다르면 확인 표시를 보여줍니다.
- 점수 수정은 점수만 변경합니다. 참가자 오연결은 해당 게임 삭제 후 올바른 이름으로 재등록하고 정산을 확인하세요.
- 대화료는 방문마다 1번 적용하며 개인별 면제·금액 변경이 가능합니다.

## OCR와 운영 범위

브라우저에서 Tesseract.js로 인식하며 별도 유료 AI API 키는 필요 없습니다. 인식 엔진·영어 인식 데이터는 사이트에 함께 배포됩니다. 첫 OCR 때 이 데이터를 사이트에서 불러오므로 인터넷 연결이 필요합니다. 사진은 최대 1600px로 줄여 보관합니다. 어두운 사진·반사·다른 점수판·원근 왜곡·문자 모양에 따라 인식 실패나 오독이 발생할 수 있으며, 자동 인식은 후보 생성이고 확인을 거쳐야 저장됩니다. 최종 숫자 영역을 직접 지정하여 재인식하거나 수기 입력할 수 있습니다.

사진·점수·이름·정산 데이터는 로그인 없이 조회하도록 설계했습니다. URL을 모르는 사람도 데이터를 발견할 수 있으므로 링크 자체를 접근 제한으로 취급하지 마세요. 사진 저장소도 공개입니다.

소규모 모임을 위해 JSON 문서 하나를 저장합니다. revision 검사로 다른 창의 변경을 덮어쓰지 않게 합니다. 기록 규모가 크게 증가하면 방문/게임별 관계형 테이블로 분리하는 것이 좋습니다. 자동 실시간 동기화 대신 새로고침 버튼을 제공합니다.

백업은 JSON 데이터이며 클라우드 사진은 URL로 포함합니다. 사진 바이트 전체를 보존하는 클라우드 백업은 아닙니다. 이전 저장소/사진이 삭제되면 백업에서도 사진을 볼 수 없습니다. Supabase 비용·보관 용량은 선택한 요금제와 실제 사용량에 따라 달라집니다.

## 확인

```sh
npm test
npm run build
```

Supabase 연결 후 별도 브라우저에서 로그아웃 상태의 공개 조회와 수정 차단, 관리자 로그인 상태의 저장, 사진 업로드/조회, 새로고침 후 기록 유지, 두 창의 동시 수정 충돌 방지를 확인하세요.
